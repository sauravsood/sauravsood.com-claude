A terminal in a browser tab

I can now open a command line on the Raspberry Pi at home, or on a server at AWS, from any browser. All it takes is an email code. I didn’t open any ports or install anything.

It started with the print server →
Chapter 1

Locked out

  • My Raspberry Pi 2 runs the app that prints my shipping labels, and it sits on the home Wi-Fi. Away from home, ssh to its local address just timed out.

  • I had the same two tools as before: a locked-down work laptop that can’t install anything, and an iPhone.

  • The Pi already runs a Cloudflare Tunnel for print.sauravsood.com, with Cloudflare Access asking for a one-time email code before anyone gets in. The plan was to reuse it.

Chapter 2

ssh.sauravsood.com

  • In Cloudflare’s Zero Trust dashboard I opened the existing tunnel and added a route: subdomain ssh, service URL ssh://localhost:22. Cloudflare had renamed "Public Hostname" to Routes, and the form wants the type written as a URL prefix.

  • In Access I added a self-hosted app for ssh.sauravsood.com, allowed only my email, and switched on browser-based SSH.

  • Now I open the address, type the code from my email, log in with the Pi’s username and password, and get a full terminal in the tab. There’s no VPN and nothing installed, and the Pi only makes an outgoing connection.

Chapter 3

What tripped me up

  • Tunnel status: DownCauseThe Pi itself was offline.FixA power cycle.

  • Ctrl+V does nothing in the web terminalCauseThe browser terminal uses a different paste shortcut.FixCtrl+Shift+V.

  • Local SSH failing at home, while the tunnel was healthyLikely causeProbably power saving on the Pi’s USB Wi-Fi adapter.FixTurn power saving off with iw dev wlan0 set power_save off, and set wifi.powersave 2 in NetworkManager so it stays off.

Chapter 4

ec2.sauravsood.com

  • Next I wanted the same email-protected terminal for a new Ubuntu server on AWS EC2. I got the first shell through AWS’s own EC2 Instance Connect, in the browser.

  • In Cloudflare I made a second tunnel called ec2 and pasted its install command into that shell.

  • EC2 logs in with keys, so I set a password with sudo passwd ubuntu and turned on password login with a small file, /etc/ssh/sshd_config.d/99-password.conf, holding PasswordAuthentication yes. Then I restarted SSH.

  • I added an ec2 route to ssh://localhost:22, plus an Access app with browser SSH and the same email rule. The address shows Cloudflare’s login, then an SSH prompt that takes a password or a pasted private key, so the .pem file works too.

  • Because the tunnel connects outward, port 22 can be closed in the AWS security group. Then the server has no SSH open to the internet at all.

  • PendingLogging in with the password on ec2.sauravsood.com isn’t confirmed yet. I’ll update this once it works.
